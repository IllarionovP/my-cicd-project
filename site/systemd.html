⚙️ Модуль 3: Системное администрирование и Безопасность

На этом этапе мы перевели управление нашей инфраструктурой деплоя на уровень операционной системы Linux с помощью менеджера инициализации Systemd.

1. Архитектура Юнитов: Системный уровень vs Пользовательский

В Linux система systemd жестко разделяет зоны ответственности:

  • Системные службы (System level): Файлы конфигурации лежат в /etc/systemd/system/. Они запускаются от имени суперпользователя root в момент включения компьютера, когда на сервер еще никто не вошел. Они работают автономно.
  • Пользовательские службы (User level): Файлы лежат в ~/.config/systemd/user/. Они работают только от твоего имени (юзера) и умирают, как только ты делаешь logout (выходишь из консоли).

2. Столкновение с SELinux в Fedora

Скрипт GitHub Actions прописал нашего робота как системную службу в папку /etc/systemd/system/, но при этом заставил её запускать исполняемый файл из твоей домашней папки /home/sasuke/ от имени пользователя sasuke.

Подсистема безопасности SELinux заблокировала этот запуск (ошибка status=203/EXEC Permission denied). Для неё запуск общесистемного сервиса из приватной домашней папки обычного юзера выглядит как классическая хакерская активность (подмена бинарника).

Как мы это победили:

Мы использовали команду смены контекста безопасности: sudo chcon -R -t bin_t /home/sasuke/actions-runner/. Мы явно объяснили ядру Linux, что файлам внутри этой папки можно доверять и они имеют право на исполнение системными демонами.

3. Настоящий стандарт Linux-администрирования

Инструмент ./svc.sh — это просто временная обертка для новичков. Как профессионалы, мы управляем роботом через стандартные утилиты операционной системы:

# Проверить статус службы деплоя (используем маску *, чтобы не писать длинное имя)
sudo systemctl status actions.runner.*

# Остановить автоматический прием обновлений с GitHub
sudo systemctl stop actions.runner.*

# Запустить бегунка обратно на дежурство
sudo systemctl start actions.runner.*

# Посмотреть живые системные логи работы нашего бегунка
sudo journalctl -u actions.runner.* -f
