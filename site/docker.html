📦 Глубокое погружение: Контейнеризация и Docker

Главное прозрение этапа: Docker-контейнер — это изолированная коробка. Когда мы работаем с Docker, мы полностью разделяем окружение нашей виртуалки Fedora и окружение самого приложения.

1. Анатомия Dockerfile

Наш сценарий сборки состоит всего из двух строк, но они фундаментальны:

FROM nginx:alpine
COPY site/ /usr/share/nginx/html/
  • FROM nginx:alpine — Мы не ставим Nginx на Fedora через dnf install. Мы берем официальный, микроскопический готовый шаблон (образ) Nginx на базе сверхлегкого дистрибутива Alpine Linux. Весь веб-сервер уже настроен внутри этого шаблона разработчиками.
  • COPY site/ ... — Эта команда берет файлы из нашей локальной папки на Fedora и копирует их внутрь изолированной файловой системы будущего контейнера.
💡 Ловушка путей: На самой Fedora пути /usr/share/nginx/html/ не существует, и самого Nginx в системе нет. Путь существует исключительно внутри изолированной коробки контейнера, куда Nginx зашит по умолчанию.

2. Почему DevOps выбирает Docker?

  • Принцип переносимости (Portability): Наш сайт «впекается» внутрь образа. Теперь этот готовый образ можно запустить одной командой на Ubuntu, CentOS, Windows или в облаке AWS. Сайт везде запустится одинаково, ведь он везет свой Nginx с собой.
  • Чистота хоста: Сервер Fedora остается абсолютно чистым. Нам не нужно настраивать конфиги веб-сервера в основной системе, следить за конфликтами версий и зависимостей.
  • Изоляция ресурсов: Если сайт упадет или зависнет, он не утащит за собой всю операционную систему.

3. Шпаргалка по ручному управлению

# Сборка локального образа (точка в конце обязательна!)
sudo docker build -t my-app:v1 .

# Запуск контейнера в фоне (-d) с пробросом портов (-p хост:контейнер)
sudo docker run -d -p 8080:80 --name my-web-container my-app:v1

# Посмотреть только запущенные контейнеры
sudo docker ps

# Посмотреть вообще все контейнеры (включая остановленные и упавшие)
sudo docker ps -a

# Остановить работу сайта (плавное выключение контейнера)
sudo docker stop my-web-container

# Снова включить сайт (быстрый запуск спящего контейнера)
sudo docker start my-web-container

# Полностью удалить контейнер из системы
sudo docker rm my-web-container
